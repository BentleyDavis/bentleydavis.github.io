Checking Bluetooth… Band: Not connected Storage: this browser

Pull your Hume band’s
stored history in Chrome.

This page speaks the band’s own protocol over Web Bluetooth — service fff0, 16-byte command frames — and downloads its stored history: heart rate, SpO₂, skin temperature, the HRV-record fields, sleep segments, daily totals, and 10-minute activity buckets. Everything is decoded on this page and stored in this browser on this device.

Download all data (JSON) gives you the complete store — samples, daily totals, sleep, raw frames, sync history — in one file. Visualization and analysis come in a later build, on top of this data.

How to use it

  1. Open this page in Chrome on your Pixel (or desktop Chrome) — Web Bluetooth doesn’t work inside in-app browsers.
  2. Wake the band, keep it nearby, tap Connect band, and pick it from Chrome’s list.
  3. Tap Sync stored history. Leave the page open until every stream finishes, then disconnect.
  4. Your data stays stored here between visits. Download the JSON whenever you want a portable copy.

Band

Read-only by construction: the protocol’s erase mode is not implemented anywhere in this page, so syncing here can’t delete anything and the Hume app can still sync afterwards. Bluetooth allows one connection at a time — disconnect here before opening the Hume app.

Sync stored history

Each stream is requested with a START frame, paged with a CONTINUE frame every 50 frames, and read until the band’s terminator. The band returns its whole buffer every time — duplicates are dropped using the band’s own timestamps, so re-syncing never doubles data.

    Streams marked “usually empty” are ones the band’s firmware rarely fills; they’re still requested so a sync is complete.

    Stored data — kept in this browser

    Everything you sync is saved in this browser’s storage on this device (IndexedDB), so history accumulates across visits and re-syncs. It lives only here — nothing is uploaded. The planned Google hookup (Sheets or Firestore) isn’t connected yet; the JSON download below is the same format that sync will use. Clearing erases the browser store permanently, so download first if you want to keep it.

    Protocol & honest labels

    The decoders are checked right here against real frames captured from a real band. A few of the band’s fields are not what their names suggest — they’re stored raw and labelled plainly, never presented as measurements they aren’t.

    Fields that aren’t what they’re called
    • “HRV” byte (0x56, byte 9) — a device state index, not heart-rate variability. No RR intervals are ever transmitted. Shown as Band State Index.
    • Systolic / diastolic bytes — generated inside a ±10 clamp, not measured. Stored raw, labelled as raw bytes.
    • “Vascular” and “stress” bytes — the same value stored under two names in the band’s records. Both are kept raw so history stays checkable.
    How syncing works, and why the Hume app still gets everything

    Reading doesn’t consume anything: the band’s history sits in ring buffers until new data overwrites it. The START frame carries a date, but the band ignores it and returns its whole buffer — so this page and the Hume app each get everything, and dedupe happens here using the band’s timestamps. No erase command exists in this page’s code.

    Why Chrome, HTTPS, and BentleyDavis.com

    Web Bluetooth needs Chrome on Android or desktop, on an HTTPS page. This page is a single static file, so the identical file can be hosted at bentleydavis.com — same protocol code, same storage format, same JSON download. Stored data belongs to the browser and origin it was synced on, so sync from the address you plan to keep using, or move the JSON across with the download/open buttons.

    Troubleshooting
    • Band not in Chrome’s list: wake it, keep it close, and make sure the Hume app isn’t holding the connection.
    • A stream ending by “idle timeout” instead of “terminator” is recorded as such in the Syncs tab — the data received is still stored.
    • The Session log tab records the exact error Chrome returned if a connection fails.
